# Stage 3 calibration — Run 2 (2026-09-19)

Reproducible artifacts backing the "Run 2" entry in
`docs/GEOMAGNETIC_CALIBRATION_LOG.md`. Unlike Run 1, this run's
preprocessing and TS-reuse tooling now lives in `../shared/`, factored
out per Run 1's own "next steps" so future runs don't re-copy it.

## Files

| File | What it is |
|---|---|
| `control_tle_raw.csv` | Quiet-control pull: 2026-09-01 to 2026-09-06, perigee<350km, one row per (object, UTC day). 592 objects, 3,395 rows |
| `storm_tle_raw.csv` | Storm pull: 2026-09-07 to 2026-09-13 (onset through recovery), same filter/grain. 624 objects, 3,644 rows |
| `dgd_last30d.txt` | Raw NOAA SWPC "Daily Geomagnetic Data" product, saved verbatim, issued 1230 UT 19 Sep 2026 — covers both windows in one settled series |
| `real_ap_series.csv` | Output of `../shared/build_ap_series.ts` against `dgd_last30d.txt`: 236 real three-hourly (intervalStart, kpClass, ap) rows, 2026-08-21 to 2026-09-19 |
| `{control,storm}_tle_rates_with_ap.csv` | Output of `../shared/preprocessing.py`: decay rates, alt bands, phase tags, standard exclusions applied, time-weighted mean-ap matched |
| `{control,storm}_tle_rates_with_lagged_activity.csv` | Output of `../shared/lagged_activity.ts`: adds `activity_tau{6,12,18,24}h` via the real production `computeRecencyWeightedActivity()` |

## Reproducing

```bash
# From the repo root:
npx tsx scripts/calibration/shared/build_ap_series.ts \
  scripts/calibration/2026-09-19-run2/dgd_last30d.txt \
  scripts/calibration/2026-09-19-run2/real_ap_series.csv

python3 -c "
import sys; sys.path.insert(0, 'scripts/calibration/shared')
from preprocessing import load_and_compute_rates, apply_standard_exclusions, match_mean_ap, tag_phase
for name in ['control', 'storm']:
    rates = load_and_compute_rates(f'scripts/calibration/2026-09-19-run2/{name}_tle_raw.csv')
    rates['phase'] = rates['epoch'].apply(tag_phase)
    rates = apply_standard_exclusions(rates)
    rates = match_mean_ap(rates, 'scripts/calibration/2026-09-19-run2/real_ap_series.csv')
    rates.to_csv(f'scripts/calibration/2026-09-19-run2/{name}_tle_rates_with_ap.csv', index=False)
"

for name in control storm; do
  npx tsx scripts/calibration/shared/lagged_activity.ts \
    scripts/calibration/2026-09-19-run2/${name}_tle_rates_with_ap.csv \
    scripts/calibration/2026-09-19-run2/real_ap_series.csv \
    scripts/calibration/2026-09-19-run2/${name}_tle_rates_with_lagged_activity.csv
done

# Day_index-included spec (Run 1's original — shown to be collinear-compromised
# on a single-episode storm window, see log):
python3 scripts/calibration/shared/bootstrap_analysis.py \
  scripts/calibration/2026-09-19-run2/storm_tle_rates_with_lagged_activity.csv

# No-day_index spec (the one the log's Results table is built from):
python3 scripts/calibration/shared/bootstrap_analysis_no_trend.py \
  scripts/calibration/2026-09-19-run2/storm_tle_rates_with_lagged_activity.csv
python3 scripts/calibration/shared/bootstrap_analysis_no_trend.py \
  scripts/calibration/2026-09-19-run2/control_tle_rates_with_lagged_activity.csv

# Predeclared day_index admissibility check — decides, per band/tau, which
# of the two specs above is "primary" vs "sensitivity" for each window.
# Run this BEFORE reading the bootstrap output as final, not after:
python3 scripts/calibration/shared/check_daytrend_collinearity.py \
  scripts/calibration/2026-09-19-run2/storm_tle_rates_with_lagged_activity.csv --label storm
python3 scripts/calibration/shared/check_daytrend_collinearity.py \
  scripts/calibration/2026-09-19-run2/control_tle_rates_with_lagged_activity.csv --label control
```

`{control,storm}_tle_raw.csv` can only be regenerated by re-running the
query template in the log's "Run 2" §1 against the production database
at the appropriate `$START`/`$END` — not derivable from anything else
checked in here.

See `docs/GEOMAGNETIC_CALIBRATION_LOG.md`'s "Run 2" entry for the full
writeup: the predeclared day_index admissibility rule
(`check_daytrend_collinearity.py`, threshold |r|>=0.8), the per-window
primary-spec CI table, the band mismatch against Run 1's addendum, and
why this run does not clear the bar for touching any production
constant.
